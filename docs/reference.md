UBIQCOM UB5021 GVW-D. Facts below were read from the live device, not from a sibling
firmware, unless marked otherwise. Credentials are deliberately absent: they live in
`captures/`, which is gitignored.

Companion docs: `tr069.md` (the ACS investigation), `cli.md` (CLI map), and
`notes/lockout.md` (the original lock-out).

## Access routes, as they actually work

| route | reachable from | auth | lands on |
|---|---|---|---|
| ssh `excitel@fe80::f6bd:b9ff:feaa:bb89%wan` | JIDU only (the ONU's L2 segment) | `/var/passwd` | `/bin/cli` — restricted tree |
| telnet `192.168.1.1:23` | LAN, after `config remoteaccess telnet lan "allow"` | MIB `TELNET_USER` / `TELNET_PASSWD` | same `/bin/cli`, or `/bin/sh` after the passwd swap |
| ftp `192.168.1.1:21` | LAN, after `config remoteaccess ftp lan "allow"` | MIB `FTP_USER` / `FTP_PASSWD` | **root, unchrooted, whole filesystem r/w** |
| web `http://192.168.1.1` | LAN | MIB `SUSER_*` | `boa` |
| web `https://192.168.1.1` | LAN | same | self-signed, `O=Default Company Ltd` |
| TR-069 | outbound only | CPE → ACS | `cwmpClient` |
| UPnP | `52881` | none | Realtek `miniigd` |

Two non-obvious bits: port 22 is filtered on IPv4 from every path but answers over IPv6
link-local, and ssh/telnet/ftp all take their credentials from the MIB rather than from
`/etc/shadow` (there is no shadow file).

## Accounts and the auth model

`/etc/passwd` is a **symlink to `/var/passwd`**, regenerated by `configd`/`prmt_apply`
from the MIB. Current shape (`captures/ftp-passwd.orig` keeps the original):

```
excitel:<md5>:0:0::/tmp:/bin/cli
user:<md5>:1:0::/tmp:/bin/cli
nobody:x:0:0::/tmp:/dev/null
```

- `excitel` is already **uid 0**. The lock was never privilege, it was the shell field:
  `/bin/cli` is a command tree, not a shell.
- There is no `/etc/group` and no `/etc/shadow`.
- Web accounts (`root`, `excitel`, `user`) are a separate store behind `boa`; `root` is
  not in `/var/passwd` at all.
- Relevant MIB keys: `SUSER_NAME`/`SUSER_PASSWORD` (web super user),
  `TELNET_USER`/`TELNET_PASSWD`, `FTP_USER`/`FTP_PASSWD`, `SSH_PASSWD` (empty),
  `CF_PASS_DECRY_ENABLE=0` — so passwords are plaintext in the config, no `PWI` blobs on
  this build.

### Getting a root shell (done once, not persistent)

`/bin/ftpd` runs as root, so writing `/var/passwd` changes the login shell:

```sh
# on the box, /bin/cli is the shell now; via FTP:
STOR /var/passwd   # excitel line ends :/bin/sh instead of :/bin/cli
```

then `ssh excitel@fe80::…%wan` gives a uid-0 `#` shell. **Verified: the same swap also
applies to telnet**, which means the shell is reachable from the LAN over
`telnet 192.168.1.1` (MIB `TELNET_USER`/`TELNET_PASSWD`) with no IPv6 hop through the JIDU.
That is the cheaper route. `/var` is ramfs, so a reboot or any MIB account write reverts it.
`captures/ftp-passwd.orig` restores the original.

The busybox build has **no `id`, `uname`, `whoami`, `head`, `tail`**, and `ps` takes no
options — `cat /proc/self/status | grep -i uid` is the reliable privilege check.

## Config layering, and why writes look like they fail

- The CLI (`/bin/cli`), the web UI (`boa`), and TR-069 (`cwmpClient`) all write the same
  MIB. `config save` flushes it to `/var/config/lastgood.xml` (yaffs2).
- Daemons read the MIB **at start**. A CLI write updates the MIB and `show …` immediately,
  but the running daemon keeps the old value until it is restarted. `config tr069
  disable/enable` is the documented way to bounce `cwmpClient`; the same applies to
  `dnsmasq`, `udhcpd`, `boa`.
- The CLI is single-instance: a second session gets `CLI busy !!`. The holder is in
  `/var/run/cli.pid`.
- `/var/dnsmasq.conf` is generated with ISP resolvers **bound to the PPPoE source
  address** and pins `pulse.excitel.in` and `gz.gdqoe.ct` to them, so neither
  `config dns` nor any DNS redirect changes what the box resolves. `config dns` only
  changes what DHCP advertises.
- `config dnspool ip "a" "b"` does feed the DHCP/DNS path, and setting it stopped the ONU
  answering DHCP (the JIDU's `udhcpc` reported no lease). Both daemons were still
  running, so it is config state, not a crash. Reverting is `config dnspool clear`.

## Recipes

Pull a file off the box (root FTP, unchanged credentials from the MIB):

```bash
curl -s --list-only "ftp://$FTP_USER:$FTP_PASSWD@192.168.1.1/var/config/"
curl -s "ftp://$FTP_USER:$FTP_PASSWD@192.168.1.1/var/config/lastgood.xml" -o captures/ftp-lastgood.xml
```

Push a cross-built binary (static, `mips-linux-musl`, mips32r2, no PIE, nothing newer than
kernel 3.18):

```bash
zig build-exe -target mips-linux-musl -mcpu=mips32r2 -O ReleaseSmall tool.c
curl -T tool "ftp://$FTP_USER:$FTP_PASSWD@192.168.1.1/var/tmp/tool"
# then on the box: chmod +x /var/tmp/tool && /var/tmp/tool
```

fastfetch for the box, same idea but through cmake (zig ships only as a python wheel, so
`uv`):

```bash
./tools/build-fastfetch-mips.sh    # -> build/fastfetch-mips/build/fastfetch
```

What that script pins down, and why:

- `zig cc -target mips-linux-musleabi -mcpu=mips32r2`. The `musleabi` ABI is required: zig
  has no libc for plain `mips-linux-musl`, and this mips is big-endian, so no `mipsel`.
- static, `MinSizeRel`, LTO off → 1.6 MB stripped (2.2 MB with everything compiled in).
- the ~45 modules that need a desktop, GPU, battery, bluetooth or USB are compiled out
  (`MODULE_DISABLE_*`), and every package manager except `opkg` is removed
  (`PACKAGES_DISABLE_*` + `PACKAGES_REMOVE_DISABLED`) — that is the 0.6 MB.
- what survives is os, host, kernel, uptime, cpu, memory, disk, netio, localip, dns, users,
  shell, datetime, loadavg, processes, logo and the format-string plumbing.
- no `pkg-config` for the target, so every optional library drops out on its own, and the
  binary reports nothing beyond `/proc`. `fastfetch --list-features` on the box is the only
  honest answer to what made it in.
- `ENABLE_LIBZFS=OFF`: enabled, it links `-lzfs` unconditionally, and there is no zfs here.
- `BINARY_LINK_TYPE` left at `dlopen` (the default): `static`/`dynamic` makes fastfetch add
  `-Wl,--copy-dt-needed-entries`, which zig's linker rejects outright.
- `-Wno-date-time`: `version.c` uses `__DATE__`/`__TIME__` and the project builds with
  `-Werror`.

Not yet run on the unit — the box was not reachable when this was built.

CLI from a root shell:

```sh
/bin/cli           # then: config …, show …, config save, exit
```

Disable TR-069 for good, and undo it:

```
config tr069 disable / config tr069 enable
config save
```

Verify it is really off: `curl -m 3 http://192.168.1.1:7547/` answers while enabled and
fails to connect once disabled.

## Dangerous, and deliberately untouched

- `xmlconfig -w` / any `mtd_util` or `flash_erase` use: writes the config partition or the
  boot slots. `mtd4..mtd13` are the A/B firmware pairs; guessing here bricks the unit.
- `Download` (TR-069 FileType 3): full MIB write, can re-lock or brick.
- Factory reset: wipes the PPPoE config, and recovery depends on the ACS that is now
  disabled.
